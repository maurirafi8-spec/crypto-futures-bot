O QUE FOI CORRIGIDO

1) JSON ESTRUTURADO
A chamada agora pede uma resposta com schema fixo:
- decision
- confidence
- risk
- style
- reason
- warnings

O request usa provider.require_parameters=true para evitar provedores
que ignorem o parâmetro de formato estruturado.

2) EXTRAÇÃO MAIS RESISTENTE
Antes o bot só lia:
choices[0].message.content

Agora tenta, com segurança:
- message.content string
- message.content em partes/array
- choice.text
- output_text
- function_call.arguments
- tool_calls.function.arguments

Ele NÃO usa reasoning interno como decisão.

3) RESUMO SEGURO DE DIAGNÓSTICO
Quando a resposta vem vazia ou inválida, o erro registra somente metadados:
- modelo servido
- provider
- finish_reason
- quantidade de choices
- tipo/tamanho de content
- existência de reasoning
- quantidade de tool calls
- tamanho do corpo HTTP

O conteúdo bruto da resposta NÃO é despejado no Telegram.

4) OPENROUTER RESCUE AUTOMÁTICO
Se a primeira resposta vier vazia ou com JSON inválido:
- o bot pode fazer UMA segunda tentativa independente;
- por padrão usa openrouter/free novamente;
- como o Free Router escolhe modelos gratuitos compatíveis, a segunda
  tentativa pode ser servida por outro modelo;
- o rescue usa prompt mais curto e temperature 0.

IMPORTANTE:
1 candidato novo por scan continua valendo.
Porém esse candidato pode consumir:
- 1 request se funcionar de primeira;
- até 2 requests se precisar de rescue.

AMBOS contam no limite diário de 45.

5) NÃO RETENTA ERROS QUE NORMALMENTE NÃO MELHORAM COM RESCUE
Não faz segunda chamada para:
- HTTP 400
- 401
- 402
- 403
- 429

Isso evita desperdiçar cota com chave inválida, permissão, crédito,
rate limit ou parâmetros rejeitados.

6) /STATUS
Agora mostra:
🛟 Rescue IA: ATIVO
🧩 JSON estruturado: ATIVO
🛟 Modelo rescue: openrouter/free
🛟 requests extras usados hoje

7) /DEBUG
Diferencia:
📡 Requests novos à IA
🛟 Requests de rescue
✅ Análises concluídas
⚠️ Falhas
⚡ Candidatos prioritários chamados
♻️ Cache

VARIÁVEIS OPCIONAIS NO RENDER
Não precisa criar nenhuma. Defaults:

AI_RESCUE_ENABLED=true
AI_RESCUE_MODEL=openrouter/free
AI_STRUCTURED_OUTPUT=true
AI_TIMEOUT_MS=25000

Se quiser desligar o rescue:
AI_RESCUE_ENABLED=false

- score mínimo 70

- candles fechados
- prioridade score 85+ / volume 1.00x+ / OI +0.50%+
- gap prioritário 5 min
- gap normal 30 min
- cache normal 30 min
- cache prioritário 10 min
- limite interno 45 requests/dia
